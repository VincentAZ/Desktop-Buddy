# Desktop Buddy rebuild and code audit — October 26, 2026

The screenshot's tool-calling error was generated by Buddy before making an inference request. `ProviderConfig.tools` defaulted to false, selecting a model reset it to false, and the agent treated that untested flag as proof that tools were unavailable. The provider had not rejected Sol.

The replacement interface is a native GTK task screen with a restrained light palette, a readable conversation column, optional history, everyday task suggestions, and “Help me do it” / “Just discuss” controls. Model choice stays visible; thinking level, offline mode, working folder, computer connection and usage are inside Task options. Responses render common headings, bold text, lists and code with escaped markup. Action details remain inspectable. Approval dialogs explain the action before showing technical details. The layout was rendered and inspected at 760×640, 940×700 and 1180×860.

![Rebuilt Desktop Buddy](screenshots/desktop-buddy-redesign.png)

## Scope and method

Manual review covered every production Python module in `desktop_buddy/`: entry point, paths, state/keyring, security, provider protocols, inference subprocesses, agent/history handling, filesystem and system tools, browser, desktop portal/accessibility, ComfyUI, conversation widgets/controller and model setup. The source launcher, package metadata, installer, test runner and bundled workflow instructions were also reviewed. Generated `build/` copies and `docs/research/` reference snapshots are not independent production implementations.

The baseline suite passed 81 tests despite the reported failure. New regressions target the missing behaviors rather than treating that baseline as evidence of correctness. Tests use isolated state directories, synthetic keys and local HTTP servers; they do not submit the user's conversation to paid services. No user conversations, credentials or working files were deleted for this rebuild. A source-only pre-change backup is at `/tmp/desktop-buddy-before-redesign.tgz` (temporary, not a durable backup).

## Findings and repairs

| Finding | Repair | Evidence |
|---|---|---|
| Untested tools were treated as unsupported, blocking Sol before inference | Capabilities distinguish automatic/unknown from explicit off. One-time migration repairs legacy false flags in saved providers and profiles. Optional probes no longer disable tools just because a model replies in text. | Capability migration and end-to-end tool execution regressions |
| The same false-by-default pattern blocked image inputs | Image permission defaults to automatic, with an explicit text-only override; legacy settings migrate with tool settings. Actual unsupported requests report the provider's error. | Existing image persistence/payload tests and explicit image-denial regression |
| Sol could be configured with incompatible API/thinking choices | Exact `gpt-6.1-sol` profiles use Responses when tools are allowed; old none/minimal preferences become low. Its menus exclude these unsupported levels. | Sol request/payload regression; official model contract below |
| Starting a task could clear a message/attachments before keyring or backend failure | Save the user message and image references before worker initialization. Record startup failure durably and restore usable controls. Agent does not duplicate the presaved message. | Native startup-failure test and presaved-message regression |
| Desktop-service initialization could break chat/file tasks | Initialize the portal and AT-SPI only when a desktop tool uses them. Failed initialization remains retryable. | Lazy-backend failure/retry test |
| Drafts leaked across conversations; failed status lingered in new conversations | Save/restore text drafts by conversation; clear stale task state; retain drafts across clean restart. Deleting a conversation removes its draft and unsent attachments. | Native draft/switch/delete/recovery tests |
| Failed-task details disappeared after reloading history | Restore the most recent task error from its audit record and show Continue task. | Native error/history test |
| Titles could grow into multiline headers | Normalize new titles to one line and constrain displayed historical titles. | Native compact layouts and rename/search suite |
| Refreshing history during a task could clear streaming status | Ignore history-selection callbacks while the task worker is active. | Existing model-switch/task isolation suite |
| Generic HTTP errors hid the actual provider problem | Include a bounded, credential-redacted provider error message. | HTTP-error redaction regression |
| Changing API format could replay incompatible native reasoning data | Replay only native structures compatible with the selected wire format; preserve normalized text/tool exchanges. | Protocol-switch and existing cross-provider reasoning tests |
| Anthropic initial text blocks could be omitted | Assemble final text from complete content blocks. | Initial-text-plus-delta regression |
| Invalid thinking budgets and nonfinite prices passed setup validation | Require a valid Anthropic budget below the response limit and finite prices. | Configuration validation regression |
| Model-check controls could change beneath an in-flight operation | Disable request-affecting controls while busy; provider changes invalidate old callbacks. | Native stale-discovery/provider-switch tests |
| File replacement stripped executable/read permissions | Preserve existing ordinary permission bits while keeping new files private. | Executable-file rewrite regression |
| File move failure could leak the first directory descriptor | Close it if opening the destination fails. | Inspection of both failure and success cleanup paths |
| Cancellation immediately after process creation could skip cleanup | Put process tracking inside inference/shell cleanup scopes, ensuring reaping and descriptor cleanup even if tracking raises. | Existing stalled-inference and shell cancellation tests; cleanup-path review |
| Successful HTTP headers followed by cancellation leaked the response | Close the response before propagating cancellation. | Cancel-after-headers regression |
| Browser navigation could report the previous loaded document | Wait for the navigation's new loader before accepting page inspection. | Loader-transition regression and real browser workflow |
| Dead browser restarts/failed startup could leak pipes or cross-deliver reader errors | Clean up dead processes, close failed-spawn descriptors, isolate pending maps per reader, synchronize process publication/close, and close failed initialization. | Real browser workflow and cleanup-path review |
| A delayed portal Closed event could clear a newer session | Match the session path, unsubscribe old listeners, and check cancellation before publishing readiness. | Old-session/new-session regression |
| ComfyUI could claim success without a successful completion status | Require explicit completed/success status. | Missing-status regression and existing live local fixture jobs |
| ComfyUI output node identifiers could contain path separators | Reject unsafe identifiers before constructing filenames. | Path-traversal regression |
| ComfyUI workflow paths bypassed pre-approval protected-path checks | Validate workflow and output paths in host policy before requesting compute approval. | Protected-workflow regression |
| Concurrent provider saves could overwrite one another | Hold the store's reentrant lock across configuration/profile read-modify-write. | Code-path review; existing model persistence suite |

## Verified results

- 103 deterministic unit/integration tests pass (`./scripts/run-tests.sh`).
- Native redesign tests pass: per-conversation drafts, startup failure persistence, recovered controls, failed-state reset, draft deletion, and compact/full-size layout renders.
- Native model setup/switching tests pass: discovery, catalog search, optional probe, thinking persistence, cross-provider history, switching the next request during an active task, stop-and-switch, stale-result suppression, and offline enforcement.
- Native conversation lifecycle tests pass: image attachment/removal, keyboard actions, rename/search, cancel/confirm deletion, history images, and memory editing.
- Native UI agent fixture creates and reads back a file; switches to Ollama's protocol; denies an approval; cancels a task via Stop everything; activates an existing process on second launch; and preserves state in a separate restart process. Observed stop latency was approximately 0.2 seconds for this fixture.
- Real isolated Chromium form fill/click, filesystem write/readback, and dedicated terminal readback pass. Real AT-SPI invokes a button in a dedicated test window and observes its changed state.
- Version 0.2.0 built and installed offline into an isolated private environment; the installed package was imported outside the checkout, its Sol defaults checked, and its native window smoke-tested. The personal application-menu installation was not changed.
- Widget screenshots were visually inspected. One optional history screenshot immediately after closing a modal was unavailable from the compositor; the history-image widget assertion passed. Dedicated welcome/error/setup screenshots rendered successfully.

## Limits and residual risks

This is a full first-party source review with targeted fixes, not a proof that the application has no bugs. No paid/live Sol or other cloud-model acceptance call was made. The tests establish request construction and host behavior, not the success of the user's DaVinci Resolve/Gmail/license workflow. Live provider availability, account access and arbitrary model support still depend on the selected service. Unknown capabilities are attempted, not labeled “verified.”

Physical pointer/keyboard control through a newly granted GNOME screen/input session was not re-authorized in this pass; portal input behavior has unit coverage and accessibility/browser control was exercised independently. Desktop permission and app focus remain environment-dependent.

Ordinary HTTP tool and ComfyUI reads use bounded socket timeouts, so their stop latency can exceed the fast inference-subprocess stop result. Stop cannot undo already completed effects. Shell approval still grants the specified command the ordinary user's privileges; it is not a filesystem sandbox outside offline mode. Other applications and local services may make their own network requests.

The process already open before the rebuild retains its imported old code. Close and reopen Desktop Buddy to load the new interface and migrate saved capabilities. This does not delete conversations or keys. Unsent image attachments are still temporary and are removed on a clean close or conversation change; text drafts now persist.
