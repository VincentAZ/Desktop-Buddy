Install, verify and launch desktop software on Ubuntu with one authenticated command, not a polling loop.

1. Identify the exact package before changing anything. If the user names a product with several variants (web wrapper, official client, community fork), ask once which they mean. Check what exists: `snap find NAME`, `apt-cache policy NAME`, `flatpak search NAME`, plus `snap list`, `dpkg -s NAME`, `flatpak list` for what is already installed. Prefer the official or distribution-supported source.
2. Installation needs administrator rights. Run exactly one install command through pkexec, for example `["pkexec","snap","install","NAME"]` or `["pkexec","apt-get","install","-y","NAME"]`, with `timeout` 1800 or more. The user sees GNOME's authentication dialog; tell them to expect it and never ask for or handle their password. Flatpak user installs (`flatpak install --user -y flathub ID`) need no authentication.
3. Wait for that command to return. Do not run `snap changes`, `ps` or status checks in a loop while it runs; the tool blocks until completion or timeout. If it times out, check once (`snap changes`, `dpkg -s`) whether the backend finished the job before trying again.
4. Verify once: `snap list NAME`, `dpkg -s NAME` or `flatpak list` must show the package. Then launch it with app.launch using the desktop ID from system.inspect (snaps register `NAME_NAME.desktop`, flatpaks `ID.desktop`) and confirm a window via desktop.accessibility.
5. Only after the replacement works, remove anything the user asked to replace (old launchers, web-app shortcuts). Report what was installed, from which source, and how it was verified.
